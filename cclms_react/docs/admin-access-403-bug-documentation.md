# CCLMS Admin Access 403 Bug Fix

## Date

2026-10-01

## Summary

The CCLMS Admin Owner Management actions were returning HTTP 403 with:

```json
{
  "success": false,
  "message": "Admin access required"
}
```

The error occurred when the frontend called the `smart-action` Supabase Edge Function to create, update, or delete an owner.

## Exact Source of the Error

The response was generated by:

`supabase/functions/smart-action/index.ts`

The authorization guard verifies the authenticated Supabase Auth user against the existing `public.profiles` table. The same authorization pattern also exists in these Edge Functions:

- `supabase/functions/create-store-owner/index.ts`
- `supabase/functions/update-store-owner/index.ts`
- `supabase/functions/delete-store-owner/index.ts`

Owner Management currently uses `smart-action`.

## Authentication Flow

1. The admin signs in through Supabase Auth.
2. The browser obtains the current Supabase session.
3. Owner Management sends the current access token as:

   ```http
   Authorization: Bearer <access-token>
   ```

4. The Edge Function extracts the bearer token.
5. Supabase Auth validates the token and returns the authenticated user.
6. The Edge Function uses that user's UUID to query `public.profiles`.
7. The matching profile must have:

   ```text
   role = admin
   status = active
   ```

8. Only then can the requested owner-management action continue.

## Root Cause

The original authorization check used the incoming authorization header indirectly and queried the admin profile with `.single()`:

```ts
const { data: adminProfile, error: profileError } = await serviceClient
  .from("profiles")
  .select("role")
  .eq("id", adminUser.id)
  .single();

if (profileError || adminProfile?.role !== "admin") {
  return response({ success: false, message: "Admin access required" }, 403);
}
```

This combined several different failures into one 403 response:

- No matching profile row.
- A database query error.
- A profile with a non-admin role.
- An inactive admin profile.

It also did not explicitly verify the profile status.

The authorization check does not use `user_metadata` or `app_metadata`. The source of truth is the existing `public.profiles` row.

## Fix Implemented

### Frontend token forwarding

`OwnerManagement.jsx` now gets the current session before every `smart-action` request and explicitly sends the access token:

```js
async function invokeAdminAction(body) {
  const {
    data: { session },
    error: sessionError,
  } = await supabase.auth.getSession();

  if (sessionError) {
    throw sessionError;
  }

  if (!session?.access_token) {
    throw new Error("No active admin session. Please log in again.");
  }

  return supabase.functions.invoke("smart-action", {
    body,
    headers: {
      Authorization: `Bearer ${session.access_token}`,
    },
  });
}
```

This helper is used for create, update, and delete owner actions.

### Edge Function authorization

The Edge Function now:

- Extracts the bearer token explicitly.
- Calls `auth.getUser(accessToken)` with that token.
- Uses the returned Auth UUID as `profiles.id`.
- Queries `role` and `status` from `public.profiles` using the service-role client.
- Uses `.maybeSingle()` so a missing profile can be distinguished from a query error.
- Requires both `role = 'admin'` and `status = 'active'`.
- Returns HTTP 403 for missing, non-admin, or inactive profiles.
- Returns HTTP 500 when the profile verification query itself fails.

The service-role key remains server-side in the Edge Function environment and is never sent to the browser.

## Final Authorization Logic

```ts
const authorization = request.headers.get("Authorization");
const accessToken = authorization?.replace(/^Bearer\\s+/i, "").trim();

if (!supabaseUrl || !serviceRoleKey || !accessToken) {
  return response(
    {
      success: false,
      message: "Missing server configuration or authorization",
    },
    401,
  );
}

const adminClient = createClient(supabaseUrl, serviceRoleKey, {
  auth: { autoRefreshToken: false, persistSession: false },
});

const serviceClient = createClient(supabaseUrl, serviceRoleKey, {
  auth: { autoRefreshToken: false, persistSession: false },
});

const {
  data: { user: adminUser },
  error: userError,
} = await adminClient.auth.getUser(accessToken);

if (userError || !adminUser) {
  return response({ success: false, message: "Unauthorized" }, 401);
}

const { data: adminProfile, error: profileError } = await serviceClient
  .from("profiles")
  .select("role, status")
  .eq("id", adminUser.id)
  .maybeSingle();

if (profileError) {
  return response(
    { success: false, message: "Unable to verify administrator access" },
    500,
  );
}

if (
  !adminProfile ||
  adminProfile.role !== "admin" ||
  adminProfile.status !== "active"
) {
  return response({ success: false, message: "Admin access required" }, 403);
}
```

## Diagnostic Logging

The Edge Function logs only non-sensitive authorization information:

- Authenticated user UUID.
- Profile role.
- Profile status.
- Supabase Auth error code/message.
- Profile query error code/message.

It does not log:

- Passwords.
- Access tokens.
- Refresh tokens.
- Service-role keys.
- Authorization headers.

Example diagnostic output:

```text
smart-action authenticated user: <admin-user-uuid>
smart-action admin profile: {
  userId: <admin-user-uuid>,
  role: "admin",
  status: "active",
  errorCode: undefined,
  errorMessage: undefined
}
```

## Database and RLS Impact

No database records, tables, columns, roles, or RLS policies were changed for this fix.

The service-role client is used only inside the Edge Function to verify the admin profile. The browser continues to use only the Supabase publishable key.

The existing profile role values remain:

```text
admin
owner
```

## Deployment

The local Edge Function source is not automatically deployed to Supabase. Deploy the updated function from the repository root:

```powershell
supabase functions deploy smart-action
```

After deployment, reload the Admin application and test Owner Management again.

## Testing Checklist

### Active admin

- Sign in with an admin profile whose `role` is `admin` and `status` is `active`.
- Open Owner Management.
- Create, edit, activate, and deactivate an owner.
- Confirm the request succeeds.

### Inactive admin

- Set the admin profile status to `inactive` through an approved administrative process.
- Confirm Owner Management requests return HTTP 403.
- Confirm no owner-management action is executed.

### Non-admin user

- Sign in as an owner.
- Attempt an owner-management request.
- Confirm the Edge Function returns HTTP 403.

### Missing profile

- Use an authenticated Auth user with no matching `public.profiles` row.
- Confirm the Edge Function returns HTTP 403 with `Admin access required`.

### Profile query failure

- Inspect Supabase logs if profile lookup fails unexpectedly.
- Confirm the Edge Function returns HTTP 500 with `Unable to verify administrator access` rather than incorrectly reporting an authorization failure.

### Token failure

- Confirm that a missing or invalid bearer token returns HTTP 401.

## Troubleshooting

### Still receiving 403 after deployment

1. Confirm the logged-in user's UUID in the browser matches `public.profiles.id`.
2. Confirm the matching row has exactly:

   ```text
   role = admin
   status = active
   ```

3. Confirm the deployed function is the updated `smart-action` version.
4. Check Edge Function logs for the authenticated UUID and profile role/status.
5. Confirm the frontend request contains the current bearer token.
6. Confirm the frontend uses the correct Supabase project URL and publishable key.

### Receiving 401 instead

Check whether the frontend session has expired or whether the request is missing the `Authorization` header. The browser must send the current access token, not the refresh token.

### Receiving HTTP 500

The user was authenticated, but the database profile verification query failed. Check the Supabase project, table availability, database logs, and deployed function configuration. Do not disable RLS or expose the service-role key to solve this error.
