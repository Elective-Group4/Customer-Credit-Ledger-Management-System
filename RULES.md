# Elective 3 (2026) — Project Rules & Restrictions

Extracted from *Elective-3-2026* documentation instructions. These are the rules that affect **what you build / how you code the project**, not the documentation formatting itself.

## Content & Development Restrictions

1. **No emojis directly in the source code.**
2. **No dynamic content generation** — the app must not automatically produce/generate content for users.
3. **No common external information retrieval** as a primary feature of the project.
4. **Avoid features that rely on auto-generated or externally retrieved content**, including but not limited to:
   - Randomly generated quotes
   - Automatically retrieved Bible verses
   - Weather information
   - Daily facts
   - Automatically generated motivational messages
   - Automatically generated jokes
   - Random messages or similar generated content
   - Content retrieved from external websites or APIs for general informational purposes
5. The project must primarily demonstrate **your own software design, web development, interface design, logic, and implementation** — not simply display or retrieve content from external sources.

## General Project Expectations

- Project can be humorous, serious, creative, practical, or witty — but must have a distinct **personality, identity, and purpose**.
- That personality should show through:
  - Name and branding
  - Purpose and concept
  - User experience
  - Interface and visual design
  - Content and overall presentation
- Must go **beyond a basic CRUD website** (per rubric: Creativity).
- Should be **original/unique**, not a generic or common system copied from other groups.
- Must clearly solve a **real/identified problem** for its target users.
- All documentation must accurately reflect the **actual implemented features** — no overstating functionality.

## Constraints (from Scope/Limitations section)

- **3-week timeline**
- Fixed **team size**
- **Tech stack limits** — must note **Vercel** and **Supabase free-tier limits**

## Deployment Notes

- Hosting: **Vercel** (frontend) + **Supabase** (backend/db)
- Never document actual secret values/keys — only the **names** of environment variables used
- Document how GitHub was connected to Vercel for auto-deploy, and any build settings used

## Rubric Weighting (for reference)

| % | Category | Key Points |
|---|----------|------------|
| 35% | Functionality | Features work as intended, correct results, working navigation/interactions, working DB/backend, few/no critical bugs, matches stated requirements |
| 25% | Creativity | Creative concept/execution, interesting UI/UX, effective use of web tech, own personality, beyond basic CRUD |
| 15% | Uniqueness | Original idea, distinct approach, not generic, has distinguishing features |
| 15% | Impact | Addresses a real problem, appropriate for target users, useful solution, purpose demonstrated |
| 10% | Documentation | Complete required sections, followed document format |
